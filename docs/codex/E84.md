# E84 · Automatické kontroly na GitHubu

Pokrývá nález 3 [auditu kódu](../audit-2026-11-28.md). Patří k [plánu refaktorizace](../plan-refaktorizace-po-auditu.md).

## Cíl

Při každém nahrání změny na GitHub se samy spustí rychlé testy, sestavení a testy datových
nástrojů. Pull request do `main` ukáže zelenou nebo červenou značku. Malá sada nejdůležitějších
prohlížečových zkoušek běží u každého pull requestu. Úplná prohlížečová sada běží pravidelně
a na vyžádání. Autor tak bez čtení kódu pozná, jestli změna něco rozbila.

## Výchozí stav

- Repozitář nemá složku `.github/`. Testy se spouštějí jen ručně.
- `npm test` trvá v kontejneru se 4 jádry 84 s, `npm run test:python` 1,5 s, `npm run build` 1,2 s.
- Prohlížečové testy (`playwright.config.js`) mají limit 90 s na test. V prostředí bez grafické
  karty trvá start hry 76–79 s, proto při auditu dva testy z `tests/e2e/game.spec.js` limit
  překročily. S limitem 400 s prošly.
- `playwright.config.js` už rozlišuje `process.env.CI` (`reuseExistingServer`).
- `.nvmrc` obsahuje verzi Node 24, `tools/requirements.txt` určuje balíčky Pythonu.
- Jeden test v `tests/test_structures.py` se přeskočí, protože úplný archiv staveb není přiložen
  k distribuované hře. Přeskočení je v pořádku.

## Rozsah

- Pracovní postup `.github/workflows/kontroly.yml` pro push a pull request.
- Značka `@zaklad` u 4–6 vybraných prohlížečových testů a jejich spuštění v pull requestu.
- Pracovní postup `.github/workflows/uplne-testy.yml` pro celou prohlížečovou sadu.
- Delší limit prohlížečových testů v prostředí CI.
- Popis v README a pravidlo v `AGENTS.md`.

## Mimo rozsah

- Nasazení hry (`gh-pages`) se nemění.
- Žádné úpravy herního kódu ani testů kromě značek a limitu.
- Kontrola stylu (`npm run lint`) přibude do kontrol až v E87.

## Postup

1. **Rychlé kontroly.** Vytvořit `.github/workflows/kontroly.yml`. Spouštět při `push` do všech
   větví a při `pull_request` do `main`. Úloha `rychle` na `ubuntu-latest`: `actions/checkout`,
   `actions/setup-node` s `node-version-file: .nvmrc` a mezipamětí npm, `actions/setup-python`
   s Pythonem 3.13 a mezipamětí pip, potom `npm ci`, `npm test`, `npm run build`,
   `pip install -r tools/requirements.txt` a `npm run test:python`. Časový limit úlohy 20 min.
   Používat jen oficiální akce `actions/*` s pevnou hlavní verzí. Commit.
2. **Limit pro pomalé prostředí.** V `playwright.config.js` nastavit `timeout` na 300 s, když je
   nastavené `process.env.CI`, jinak ponechat 90 s. Pro jednotlivé testy s vlastním
   `test.setTimeout` přidat stejné navýšení přes společnou pomocnou funkci, ne kopírováním čísel.
   Commit.
3. **Základní prohlížečová sada.** Označit značkou `@zaklad` 4–6 existujících testů, které spolu
   pokrývají: start hry a hlavní menu, uložení a obnovení po načtení stránky, jízdu autem, mobilní
   ovládání a rozpočet geometrie (`tests/e2e/budget.spec.js`). Vybírat testy, které při
   opakování nekolísají. Součet jejich běhu v projektu `webgl2` má být do 15 min na běžném
   stroji GitHubu. Seznam a důvod výběru zapsat do protokolu. Commit.
4. **Prohlížeč v pull requestu.** Do `kontroly.yml` přidat úlohu `prohlizec`, která běží po úspěchu
   `rychle` a jen pro `pull_request`. Kroky: `npm ci`, `npx playwright install --with-deps chromium`,
   `npm run build`, `npx playwright test --grep @zaklad --project=webgl2 --trace off`. Při selhání
   uložit `test-results/` a `playwright-report/` jako artefakt na 7 dní. Commit.
5. **Úplná sada.** Vytvořit `.github/workflows/uplne-testy.yml` se spuštěním `workflow_dispatch`
   a podle rozhodnutí autora také `schedule`: veřejný repozitář každou noc, soukromý jednou týdně.
   Rozdělit běh na 4 části (`--shard=1/4` … `4/4`) v matici pro oba projekty. Výsledky uložit jako
   artefakt. Tento postup nesmí blokovat sloučení pull requestu. Commit.
6. **Ověřit, že kontrola opravdu chytá chyby.** Na dočasné větvi `zkouska/cervena-kontrola`
   přidat test, který úmyslně selže. Ověřit červenou značku, uložit odkaz na běh do protokolu
   a dočasnou větev smazat. Do `main` se nic z toho nedostane.
7. **Popis pro autora.** V README přidat část „Automatické kontroly“: kde je najít (záložka
   Actions a pull request), co znamená zelená a červená značka, jak ručně spustit úplnou sadu
   a jak v nastavení GitHubu zapnout ochranu větve `main` (Settings → Branches → požadované
   kontroly `rychle` a `prohlizec`). Přidat odznak stavu kontrol na začátek README. V `AGENTS.md`
   doplnit pravidlo: pull request do `main` jen se zelenými kontrolami, červenou nejdřív opravit
   a nikdy ji neobcházet změnou testu. Commit.

## Technické poznámky

- Prohlížeč na GitHubu nemá grafickou kartu. Projekt `webgl2` používá SwiftShader podle
  `tests/e2e/browser-flags.js`. Projekt `webgpu` v úplné sadě ověřit, a pokud na běžném stroji
  GitHubu nefunguje, zapsat to do protokolu a v úplné sadě ponechat jen `webgl2`.
- Proměnnou `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` na GitHubu nenastavovat. Chromium nainstaluje
  `npx playwright install`.
- `webServer` v `playwright.config.js` spouští `npm run preview`. V CI tedy musí předcházet
  `npm run build`.
- Mezipaměť stažených balíčků zrychlí opakované běhy. Nemá ale ukládat `node_modules`.

## Testy a ověření

- Zelený běh `kontroly.yml` na větvi `etapa/E84` a v pull requestu do `main`.
- Červený běh na dočasné větvi z kroku 6.
- Jeden ručně spuštěný běh `uplne-testy.yml`. Výsledky, počty prošlých a neprošlých testů
  a délku běhu zapsat do protokolu. Neprošlé testy z úplné sady jsou informace pro další etapy,
  ne důvod etapu zastavit. Do protokolu patří jejich seznam a zda selhaly i místně.

## Kritéria přijetí

- Každý push spustí rychlé kontroly. Pull request do `main` má navíc základní prohlížečovou sadu.
- Úmyslně chybný test dá červenou značku.
- Úplnou sadu jde spustit tlačítkem v záložce Actions.
- README a `AGENTS.md` popisují kontroly. Žádný herní soubor se nezměnil.

## Výstupy

`.github/workflows/kontroly.yml`, `.github/workflows/uplne-testy.yml`, značky `@zaklad`,
úprava `playwright.config.js`, README, `AGENTS.md`, protokol `docs/E84.md`.

## Kontrola pro autora

1. Na GitHubu otevři záložku **Actions**. Poslední běh „Kontroly“ má zelenou fajfku.
2. Otevři pull request etapy. Dole jsou kontroly `rychle` a `prohlizec`, obě zelené.
3. V záložce Actions vyber „Úplné testy“ a klikni na **Run workflow**. Po doběhnutí uvidíš
   počet prošlých testů.
4. Podle návodu v README zapni ochranu větve `main`.
